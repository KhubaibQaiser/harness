## What changed since 0.2.0-beta.1

- Guard: it reads `$IFS` and every `${IFS...}` form as a space, and reads quotes and escapes inside words (`git "push"`, `g\it`) as plain words, so they can't hide a rule. Words built at run time ask when the command names `harness`, `cli.mjs`, `.harness` or `.claude/settings`.
- Protect: asks when a command names a protected path (`.harness`, `.claude`) and goes through an expansion, a glob that can match it, a redirect, a `cd` into it, `source` or a script. It also reads quoted protected paths and `xargs` and `find -exec` writers. It no longer asks for commit and PR messages or plain reads. The known gaps are listed in `docs/reference.md`.
- New `harness preset list` and `harness preset check <dir>`: list the shipped and repo presets, or check a preset folder. Both write nothing.
- New shipped preset `khubaib-frontend` (core block, engineering principles, React, Next.js and React Native skills), and `harness select --preset <id> --answers <file>`, which adds ticked rows for the preset's core and the skills that match the stack. A chosen preset is recorded as a `preset` key in the config.
- `harness git`: `git branch --suggest <topic>` prints one branch name per preset prefix. With a preset that sets `no_ai_trailer`, `git commit` refuses a set `git.commit_trailer`. With `pr_size_warning`, `git pr` prints a size warning before it creates the PR.
- PR size: new `pr_size.target_lines` (200), `pr_size.max_lines` (400), `pr_size.max_files` (20) and `pr_size.exclude` config keys, and `node .harness/hooks/dispatch.mjs --pr-size [--base <name>] [--head <name>] [--worktree]`, which measures the current branch's PR (with `--worktree`, uncommitted and untracked changes too) and prints JSON, using the branch's approved raise as its max. It exits 0 within the limit, 1 over it and 2 when it can't measure. New `pr-size` check (`checks.prSize`, on by default): before `gh pr create`, or a push to a PR branch harness recorded, goes over `max_lines` or `max_files`, it asks you first, and an unattended run is denied with how to split it. A PR it can't measure runs with a note. While a branch grows, harness also warns once as its committed and uncommitted change passes `target_lines` and once as it passes the max, after edits and at Stop, and suggests splitting it with `pr-ship`; the thresholds announced per branch are kept in `.harness/state/pr-progress.json`. After an attended warning, the agent asks you once, with AskUserQuestion under the header `PR size`; any answer lets the next edit run. If it skipped asking, the next edit on that branch asks once in a permission dialog instead (approve to keep going, or say no and split or raise the limit); unattended runs get the note only. A `PR size` question that carries its own answer is denied, so only your answer counts. AskUserQuestion gets its own PreToolUse and PostToolUse hook groups, which never block a question if the dispatcher fails, so `harness update` changes `.claude/settings.json`. After a warning, `pr-ship` asks you to split now, keep going or raise the limit for this branch: `node .harness/hooks/dispatch.mjs --pr-size-raise --lines <n> [--files <n>]`, which you approve in a dialog (denied unattended), lifts that branch's limit for the warnings and at PR time. It is recorded only on the branch the dialog named. To keep forged hook events out, a command that runs a hook dispatcher by hand without an entry flag, or copies, moves, links, pipes or redirects a hook file, is denied, attended or not. It is a text check that over-matches: `grep x .harness/hooks/dispatch.mjs | head` is denied too.
- Hooks: when several checks ask on one tool call (the PR-size pause and the multi-file gate, say, or the guard and the PR-size ask on one command), you get one dialog that lists every reason, not only the first.
- New own skill `pr-ship` (default on): it splits a change that is over the PR-size limit into stacked PRs, refactors first, then vertical slices with their tests, each opened with an explicit base.
- Stop gate: each Stop step is timed into `.harness/logs/timing.jsonl` (event, outcome, ms; no paths or command text). At 5 MB it is renamed to `timing.1.jsonl`.
- Groundwork, not yet user-facing: the usage report modules (transcript reader, session locator, token and turn counts, skill firing, gate counts, needs-a-look windows) and the rule lint table.

Everything else from 0.2.0-beta.1 is unchanged.

## Unpinned items

Every plugin and MCP server is pinned to a commit or an exact version. These run code that is not pinned, so what runs can change without a catalog change. Each is flagged in the item's evidence. Hosted MCP servers are not listed: their code does not run on your machine.

- `playwright`: runs `npx @playwright/mcp@latest`: the newest release from npm at run time
- `deploy-on-aws`: runs `uvx awslabs.aws-iac-mcp-server@latest` and `uvx awslabs.aws-pricing-mcp-server@latest` at launch
- `aws-serverless`: runs `uvx awslabs.aws-serverless-mcp-server@latest --allow-write` at launch
- `databases-on-aws`: `uvx ...@latest` for the aurora-dsql and cloudwatch servers; the vendor file marks both `disabled`, but Claude Code doesn't document that key, so they may still start
- `jfrog`: three `npx` commands name `@jfrog/agent-guard` with no version, at session start, on Skill and Read calls, and on prompt expansion
- `tdd-guard`: `npx tdd-guard@latest` in three hook events

## Known limits

The full list is in `docs/reference.md#known-limits`. This release adds 32 PR-size limits there: text detection only, the unmeasured note, the pause and the agent's question, the raise and the hand-run deny. New since 0.2.0-beta.0, unchanged in this release:

- Plugin picks are local only and are missing in cloud sessions.
- `extraKnownMarketplaces` needs folder trust.
- MCP servers need each user's approval.
- `CLAUDECODE` is also set in IDE terminals.
- There is no version-drift check for `git-subdir` plugins without `plugin_version`.
- The agent asks before item changes.
- Plugins and MCP servers aren't measured before install, and only the person installing is asked about the budget.
- Under `sandbox: always`, item commands may need the `!` prefix. Unverified, pending the live check.
