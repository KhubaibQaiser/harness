# PR size implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a `pr-size` check measures every `gh pr create`, and every `git push` to a branch harness recorded as a PR, without a shell. It asks above 400 changed lines or 20 files, denies when unattended, and notes when it can't measure. A `pr-ship` skill, installed by `init`, plans the split into stacked PRs of about 200 lines.

**Architecture:**
- `walkCommands` is extracted from the guard's `personOnlyInvocation`/`walkInvocation` (`src/checks/guard.ts:197-301`). The person-only rules become one visitor. pr-size adds a second visitor that finds PR creates and pushes.
- `src/checks/pr-size/` holds four focused files, like `src/checks/tdd/` and `src/checks/stop/`:
  - `measure.ts`: base and head resolution, the three-dot diff and the counting rules;
  - `detect.ts`: the visitor, giving `PrTarget[]`;
  - `entry.ts`: the `--pr-size` entry of `dispatch.mjs`;
  - `check.ts`: the decision, the copy and the `pr-branches.json` record.
- Every git call goes through an injected `Git` function. Tests use temporary repos (`makeRepo`) or a fake `Git`. Nothing touches the network.
- The `pr-ship` own item ships the skill template and, from Task 7, owns `checks.prSize`. `pr-create-trigger` is marked as replaced.

**Tech stack:** TypeScript, Node ≥ 22.11, esbuild bundle, Vitest, picomatch (already a dependency, through `matches`). **No new dependency.**

**Spec:** `docs/specs/2026-11-03-pr-size-design.md` (owner-approved, binding). Section numbers below (§n) refer to it. The evidence is in `docs/research/2026-11-02-pr-size.md`.

## Global constraints

- Limits (D2): target 200, ask above 400 changed lines or above 20 files. "Over" means `lines > max_lines || files > max_files` (§6).
- Counting (§5, D3, O1-O3):
  - Tests count.
  - Lockfiles, `.*ignore` files except `.npmignore` and `.harnessignore`, snapshots and `multi_file_gate.generated` paths don't count.
  - A binary file is 1 file and 0 lines. A whole-file deletion is 1 file and 0 lines. A rename is judged by its new path.
  - Only committed work counts, from the three-dot diff.
- Unmeasured (O5) allows with the §10.3 note and one `pr-size-unmeasured` event, attended and unattended. It never asks or denies.
- Trust boundary (§4): a base or head name must match `^[A-Za-z0-9][A-Za-z0-9._/-]{0,254}$` and contain no `..`. Only resolved SHAs reach `git diff`. Every lookup uses `rev-parse --verify --quiet --end-of-options <ref>^{commit}`.
- No shell: `spawnSync('git', args, { cwd, encoding: 'utf8', timeout ≤ 2000, maxBuffer: 64 MB })`, and 6 s in total per measurement.
- A command with no PR create and no push spawns no git and reads no record file (PE latency budget).
- No new regex rules in the guard's `DENY` or `ASK` (PE §3.5). The guard's tests pass unchanged.
- No changes to `src/vet/*`, `src/cli/vet.ts` or `guard.ts:302-346`.
- Copy: §10 verbatim, except for the push variant (see the owner question). Paths and branch names in any message go through `esc` (`src/core/config.ts:92`).
- Lean context: the `pr-ship` description is one line of at most 160 characters. The skill is under 60 lines.
- Tests:
  - TDD: red first.
  - Every git call goes to a temporary repo or a fake `Git`.
  - No network, no `gh` call, no `claude -p` and nothing paid. The three §11 live checks are out of this plan; they need the owner's approval as one batch.
  - The full suite must pass with `claude` off PATH: ``PATH="$(node -p "process.env.PATH.split(require('path').delimiter).filter(d=>!require('fs').existsSync(require('path').join(d,'claude'))).join(require('path').delimiter)")" pnpm test``.
  - Git fixtures pin the branch (`makeRepo(…, { branch: 'main' })`).
- Process:
  - Each task is one small PR off `main`, on branch `feature/prsize-<n>-<slug>`, merged in order before the next one starts.
  - Commit with `git -c user.name=khubaibqaiser -c user.email=khubaib.dev@gmail.com commit …`, with no AI trailer.

## Review focus

1. **A huge PR overflows the spawn buffer.** With the default 1 MB `maxBuffer`, a numstat over 1 MB fails as `ENOBUFS`. The PR would then be unmeasured and allowed, exactly the case the check exists for. `realGit` sets 64 MB (Task 3 test: a 2 MB blob read through `realGit` arrives whole).
2. **A corrupt `pr-branches.json`.** Invalid JSON, an array, or an entry with string counts must read as "no record". A throw there would deny every later push, because the check is `failClosed`. PostToolUse never throws, so the record is best effort (Task 7 test).
3. **A branch named `constructor` or `toString`.** It passes the name rule. A plain `record[name]` lookup would find `Object.prototype` members and treat an unrecorded branch as recorded. Lookups use `Object.hasOwn` (Task 7 test).
4. **Control and bidi characters in file or branch names.** They would reach the person's ask dialog raw. Every path and name in the copy goes through `esc` (Task 7 test).
5. **The skill's measuring command.** `node .harness/hooks/dispatch.mjs --pr-size --base feat/a` must pass the guard and protect without an ask, or the skill asks the person on every run (Task 4 test). Known limit: a base whose last segment is exactly a guard backstop word (`feat/sync`) still asks, because `guard.ts:306` is out of bounds here.

  - The first non-null result wins.
- The person-only rules become `personOnlyVisit(w)` together with `{ whole: <the eval rule>, script: backstop, tooDeep: <the existing "chain of npm scripts" ask> }`. `personOnlyInvocation(command, w, depth)` keeps its signature and calls `walkCommands`.

### Task 3: Measuring a PR

**Files:**
- Create: `src/checks/pr-size/measure.ts`
- Test: `test/checks/pr-size/measure.test.ts`

**Interfaces:**
- Consumes: `HarnessConfig` (Task 2), `matches`, `esc`.
- Produces:
  - `export type Git = (args: string[], timeoutMs: number) => { status: number | null; stdout: string; error?: NodeJS.ErrnoException }`.
  - `export const realGit = (root: string): Git`. It runs `spawnSync('git', args, { cwd: root, encoding: 'utf8', timeout, maxBuffer: 64 * 1024 * 1024, stdio: ['ignore', 'pipe', 'pipe'] })`.
  - `export const plainBranch = (n: string): boolean`, the §4 rule.
  - `export type SizeConfig = Pick<HarnessConfig, 'pr_size' | 'multi_file_gate' | 'stop'>`.
  - `export interface Size { base: string; head: string; lines: number; files: number; top: { path: string; lines: number }[]; excluded: string[] }`.
    - `base` is shown as `origin/<n>` when it was found in `refs/remotes/origin/`, and as written otherwise.
    - `head` is `HEAD` or the name.
    - `top` holds every counted file, sorted by lines descending, then by path.
    - `excluded` is sorted.
  - `export interface Unmeasured { error: string; base?: string }`.
  - `export function measure(root: string, want: { base?: string; head?: string }, config: SizeConfig, opts?: { git?: Git; now?: () => number; budgetMs?: number }): Size | Unmeasured`. The default `budgetMs` is 6000.
  - `export const isOver = (s: Pick<Size, 'lines' | 'files'>, c: HarnessConfig['pr_size']): boolean`.
  - `export function currentBranch(git: Git): string | null`. It runs `symbolic-ref --quiet --short HEAD` and returns null when HEAD is detached.
- Unmeasured reasons, exactly:
  - `` base `<n>` not found; fetch it first ``
  - `` head `<n>` not found ``
  - `` `--base` is not a plain branch name `` (or `` `--head` ``)
  - `no base: origin/HEAD is not set and stop.base_ref (<ref>) was not found; fetch it first`
  - `git not found` (for `ENOENT`)
  - `git timed out` (for `ETIMEDOUT`, or no budget left)
  - `git diff failed`

  Every `<n>` goes through `esc`.
- Base lookup:
  - The `--base` value; otherwise `symbolic-ref --quiet --short refs/remotes/origin/HEAD`; otherwise `stop.base_ref`.
  - Each name is tried as `refs/remotes/origin/<n>`, then `refs/heads/<n>`, then `<n>` (drift 9), each with `rev-parse --verify --quiet --end-of-options <ref>^{commit}`.
- Head lookup: `refs/heads/<n>`, then `refs/remotes/origin/<n>`; with no name, `HEAD`.
- Each call's timeout is `min(2000, deadline - now())`. When that is ≤ 0, the result is `git timed out` and no call is made.
- The two diff calls are exactly the §4 commands, with `-c core.quotePath=false` first in `args`.
- Parsing `-z` numstat (the one algorithm the signature doesn't fix): split on `\0`. Each record is `added\tdeleted\tpath`. When `path` is empty, the next two fields are `old` and `new`, and `new` is judged. `-` counts are binary: 0 lines. The `--diff-filter=D` paths (`D\0path\0` pairs) count 0 lines.
- A path is excluded when `matches(rel, [...pr_size.exclude, ...multi_file_gate.generated])`.

  - **Counting:**

    - `pnpm-lock.yaml`, `.gitignore`, `.prettierignore`, `.dockerignore`, `.eslintignore` and `pkg/.gitignore` are in `excluded` and counted in neither;
    - `.npmignore` and `.harnessignore` are counted;

    - a binary file (bytes with NUL) is 1 file and 0 lines;

    - `dir with space/ü.ts` is counted under its real name;
    - uncommitted and untracked changes aren't counted;
    - merging `main` into `feat` after `main` moved adds nothing from `main`.
  - **Base and head:**
    - `--base main` resolves to `origin/main`;
    - a stacked base `feat/a` is found on the remote, or only locally (`refs/heads`);
    - a missing base gives `` base `feat/zz` not found; fetch it first ``;
    - with `origin/HEAD` unset, `stop.base_ref: origin/main` is used;

### Task 4: The `--pr-size` entry on `dispatch.mjs`

- Modify: `src/hooks/dispatch.ts` (`main()`, right after `--self-test`)

**Interfaces:**
- Consumes: `measure`, `isOver` and `Git` (Task 3); `loadConfig`; `repoRoot`.
- Produces `export function prSizeEntry(argv: string[], cwd: string, out: (line: string) => void, git?: Git): 0 | 1 | 2`.
  - The arguments are `--pr-size [--base <name>] [--head <name>]`. It reads no stdin.

**Interfaces:**
- Consumes: Tasks 1 to 5; `appendEvent`; `writeAtomic`; `esc`.
- Produces:
  - `export const RECORD = '.harness/state/pr-branches.json'`.
  - `export interface PrRecord { base: string; lines: number; files: number; ts: string }`.
  - `export function readRecords(root: string): Record<string, PrRecord>`. It never throws. A missing or unreadable file, invalid JSON, a non-object, or an entry that fails `plainBranch(key)` or has non-integer counts is dropped. It returns an object with a null prototype.
  - `export function writeRecord(root: string, branch: string, r: PrRecord): void`, through `mkdirSync` and `writeAtomic`.
  - `export function decidePrSize(ctx: Ctx, git?: Git): Decision`. Both events go through it; the default `git` is `realGit(ctx.root)`.
  - `export const prSize: Check = { name: 'pr-size', events: ['PreToolUse', 'PostToolUse'], failClosed: true, pure: true, run: (ctx) => decidePrSize(ctx) }`. `pure` holds at PreToolUse; the dispatcher reads `pure` only after a PreToolUse deny.
- Behaviour:
  - It runs only when `ctx.config.checks.prSize` is true and `isShell(tool_name)`. `checks.guard` doesn't matter.
  - With no targets: allow, with no git spawn and no record read.
  - **PreToolUse:**
    - For each target, in order:
      - A create is measured with `{ base, head }`.
      - A push to a recorded branch is measured from `record.base` to its head: `src`, or `HEAD` when `src === 'HEAD'`. Recorded branches are those with `Object.hasOwn(records, dst)`. With `refs: []`, the branch is `currentBranch`. With `all`, it is every recorded branch whose `refs/heads/<name>` exists.
      - A push to an unrecorded branch is skipped.
    - The first over-limit create, or over-limit push that grows its record (`lines > rec.lines || files > rec.files`), decides: ask when attended, deny when unattended.
    - An over-limit push that doesn't grow allows.
    - If nothing decides and some target was unmeasured, append one `{ check: 'pr-size', decision: 'pr-size-unmeasured', reason }` event per unmeasured target. Then return `{ kind: 'context', check: 'pr-size', text: <the 10.3 notes, one per line> }`.
  - **PostToolUse:**
    - For each create, measure again and record it under its head branch: `head`, or else `currentBranch`. A detached HEAD records nothing. The base is `base`, or else `Size.base`. An unmeasured create with no record yet is recorded with `lines: 0, files: 0`.
    - For each push to a recorded branch, measure and update `lines`, `files` and `ts`, keeping `base`.
    - It never throws (`try`/`catch`, with a warning on stderr), and it always returns allow.
- Copy (§10). `L`, `F`, `B`, `T`, `ML` and `MF` stand for the measured lines, files, base, target, `max_lines` and `max_files`:
  - `largest`: `` Largest: `p1` n1, `p2` n2, `p3` n3. `` It is built from `top.slice(0, 3)`.
  - `notCounted`: `` Not counted: `x`, `y`. `` It holds the first 5, then `, and N more`, and is left out when nothing was excluded.
  - Ask, for a create:
    - First sentence: `` Confirm: this pull request is L changed lines in F files against `B`, over the limit of ML lines or MF files (aim for T). ``
    - Then the two lists.
    - Last sentence: `Approve to open it as it is, or say no and run the pr-ship skill to split it into stacked PRs.`
  - Ask, for a push:
    - First sentence: `` Confirm: this push grows the pull request for `<branch>` to L changed lines in F files (it was l0 in f0). ``
    - Then the two lists.
    - Last sentence: `Approve to push it as it is, or say no and run the pr-ship skill to split it into stacked PRs.` This is owner question option (a).
  - Deny, for a create: `` Blocked by pr-size: this pull request is L changed lines in F files against `B`, over the limit of ML lines or MF files, and no person is here to approve it. Split it with the pr-ship skill into stacked PRs of about T lines each, opening each with `--base` set to the branch before it. If a piece can't go under the limit, stop and report it. ``
  - Deny, for a push: the same, with `` this push grows the pull request for `<branch>` to L changed lines in F files (it was l0 in f0) `` in place of `` this pull request is … against `B` ``.
  - Note: `` Note from pr-size: harness couldn't measure this pull request (<reason>), so its size against the limit of ML lines or MF files wasn't checked. To check it yourself, run `node .harness/hooks/dispatch.mjs --pr-size --base <base>`. `` Here `<base>` is the name used, or the literal `<base>` when there was none.
