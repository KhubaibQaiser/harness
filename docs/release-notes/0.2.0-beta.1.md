# 0.2.0-beta.1

The first beta on npm with `/harness:vet`. Install it with `npm i -g @khubaibqaiser/harness@beta`, or as a plugin.

## What changed since 0.2.0-beta.0

- `/harness:vet` skill: runs the vet scan, has the reviewer judge the flagged files, and shows the summary. If any finding is high, it asks a second time before it prints the install commands.
- Reviewer vet mode: the `staff-reviewer` agent can judge a vet scan. It reads only the flagged files, and it can never lower a severity.
- Security fix (C1): the vet scan skipped files over 1 MB and files with a NUL byte without saying so. A malicious script padded past 1 MB, or with one NUL byte, gave zero findings. Both are now findings ("over 1 MB, not read", "binary, not read").
- Other vet scan fixes: scripts named like prose (`security-check.js`) and code under `docs/` are scanned. MCP configs and hooks files named in `plugin.json` are read whatever their extension. Hooks in skill and agent frontmatter are high findings. Skill and command `allowed-tools`, and an agent `permissionMode` other than `default` or `plan`, are findings. Frontmatter over 16 KB is a finding. Shell-running settings keys such as `statusLine` and `apiKeyHelper` are judged.
- Vet report fixes: findings print once, escaped. The `--keep` map lists only in-scope renamed files. `unsafe-archive` and allow-rule findings are capped per file, with a summary line. The skill stops if `vet --finish` fails.
- Guard fixes: the word after `harness vet` is treated as the target, so a repo named `sync` or `pr` no longer prompts. That is not applied when the command defines a function, and the `function harness { ... }` form is now denied.
- Perf test: the vet growth check compares 250 KB with 4 MB and fails above 50x. It was 4x and 8x, which flaked on macOS CI. The 4 MB cases have a 60 s timeout. Two quadratic paths and a stack overflow on 4 MB inputs were fixed.
- Catalog: each design repo has one lead design skill, and `taste-skill` leads for web and landing.
- Docs: the 0.2.0-beta.0 release notes now mention vet. README and `docs/reference.md` describe what the scan reads and reports.

Everything else from 0.2.0-beta.0 is unchanged and repeated below.

## Unpinned items

Every plugin and MCP server is pinned to a commit or an exact version. These run code that is not pinned, so what runs can change without a catalog change. Each is flagged in the item's evidence. Hosted MCP servers are not listed: their code does not run on your machine.

- `playwright`: runs `npx @playwright/mcp@latest`: the newest release from npm at run time
- `deploy-on-aws`: runs `uvx awslabs.aws-iac-mcp-server@latest` and `uvx awslabs.aws-pricing-mcp-server@latest` at launch
- `aws-serverless`: runs `uvx awslabs.aws-serverless-mcp-server@latest --allow-write` at launch
- `databases-on-aws`: `uvx ...@latest` for the aurora-dsql and cloudwatch servers; the vendor file marks both `disabled`, but Claude Code doesn't document that key, so they may still start
- `jfrog`: three `npx` commands name `@jfrog/agent-guard` with no version, at session start, on Skill and Read calls, and on prompt expansion
- `tdd-guard`: `npx tdd-guard@latest` in three hook events
- `probity`: `npx @nizos/probity` on every Bash, Write, Edit and NotebookEdit call: the local copy if installed, else the newest from npm
- `security-guidance`: installs claude-agent-sdk with pip and no version pin
- `expo`: its feedback step runs `npx --yes @expo/agent-cli@latest feedback`, only when feedback is submitted
- `shadcn`: its skill runs `npx shadcn@latest info --json` when it loads

## Known limits

The full list is in the README. New in this release:

- Plugin picks are local only and are missing in cloud sessions.
- `extraKnownMarketplaces` needs folder trust.
- MCP servers need each user's approval.
- `CLAUDECODE` is also set in IDE terminals.
- There is no version-drift check for `git-subdir` plugins without `plugin_version`.
- The agent asks before item changes.
- Plugins and MCP servers aren't measured before install, and only the person installing is asked about the budget.
- Under `sandbox: always`, item commands may need the `!` prefix. Unverified, pending the live check.
