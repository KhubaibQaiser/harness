# 0.2.0-beta.2

## What changed since 0.2.0-beta.1

Run `/harness:update` in each repo after upgrading: new hook entries (`SessionStart` `compact`, and AskUserQuestion for PR size) change `.claude/settings.json`.

### Guard and protect

- Guard: it reads `$IFS` and every `${IFS...}` form as a space, and reads quotes and escapes inside words (`git "push"`, `g\it`) as plain words, so they can't hide a rule. Words built at run time ask when the command names `harness`, `cli.mjs`, `.harness` or `.claude/settings`.
- Guard: globs, quoting, heredocs and message values can no longer hide a rule. Heredoc bodies and commit or PR messages are data only in a plain, canonical command; anything else gets the strict check. The exact rules are in `docs/reference.md#known-limits`.
- Guard: a preview of a command the agent has to ask about (`--dry-run` and the like) passes only when written out in plain words. An argument with `$`, a backtick, a brace, a glob or a leading `~` asks (denied unattended).
- Protect: asks when a command names a protected path (`.harness`, `.claude`) and goes through an expansion, a glob that can match it, a redirect, a `cd` into it, `source` or a script. It also reads quoted protected paths and `xargs` and `find -exec` writers. It no longer asks for commit and PR messages or plain reads. The known gaps are listed in `docs/reference.md`.
- Git safety: harness runs its own git calls with `--no-optional-locks` and with `core.fsmonitor`, `log.showSignature` and hooks turned off, and its `git diff` calls with `--no-ext-diff --no-textconv`, so a repo's `.git/config` can't make them run a program. Two exceptions: `filter.<name>` drivers still run (turning them off would break git-lfs), and `harness git` checkout, commit and push keep your hooks, credential helper, `core.sshCommand` and signing, since you run those steps yourself.
- Hooks: when several checks ask on one tool call (the PR-size pause and the multi-file gate, say, or the guard and the PR-size ask on one command), you get one dialog that lists every reason, not only the first.

### Context budget

- The budget (`context.budget_tokens`, default 2000) now counts the repo's own always-loaded text too: `CLAUDE.md`, `AGENTS.md`, rules (with their `@` imports), skills and agents. `init`, `update`, `add` and `sync` ask once before an install takes the total past it, and refuse a repo file the plan reads that is a symlink (`refusing symlink: <file>`).
- New `harness context [--json] [--offline]`: the always-loaded and on-demand rows by owner (`harness`, `preset:<id>`, `catalog:<id>`, `repo`), the total against the budget, what is not measured, and numbered recommendations. Writes nothing. Exits 1 when over the budget. It estimates (characters ÷ 4), or uses Anthropic's token-counting API when `ANTHROPIC_API_KEY` is set and `context.count` is `auto`; that sends the measured text to Anthropic under the key's account. New config keys `context.count` and `context.count_model`.
- New `harness context apply <n>[,<n>…] [--dry-run|--yes]`: applies harness-owned recommendations only (a skill shown by name only through `skillOverrides`, or removing a catalog plugin pick). `uninstall` undoes it. The agent has to ask before running it.
- New skill `/harness:context-optimize`: measures, proposes trims, and applies harness's own after a yes. Your own files change only after you approve each diff.
- `status` shows a `Context:` line and `doctor` one context check line. Both count offline and never call the API.
- Catalog items now record `cost.context_tokens`, measured at the pinned commit (`harness catalog check --resolve --context`, `--write-context`). 76 of the 78 plugins and external skills have a number; `impeccable` and `shadcn` are listed as not measured. MCP servers are always not measured.
- Compaction state card: a `SessionStart` `compact` hook re-adds a short card of harness state (TDD, pending harness-file changes and the like) after Claude Code compacts the conversation.

### Usage report and eval

- New `harness report [--days N] [--open] [--export]`: writes `.harness/reports/<date>.html` from this repo's Claude Code session transcripts on your machine (which skills were invoked when they were relevant, which rules a gate enforces and how each can be bypassed, token use, where a gate probably blocked something it should not have, and the always-loaded table). No JavaScript, no external requests, sends nothing. `--export` also writes counts only as `<date>-export.json`. `.harness/reports/` is gitignored. The page quotes your sessions, so don't share it. Only sessions started inside the repo or one of its worktrees count.
- New `harness eval [--kind skills|rules] [--runs N] [--max-cost-usd X] [--model <id>]`: runs `claude plugin eval` on a plugin built in a temp folder. It costs money: it asks you to type `yes` every run, stops at a ceiling (default $2) and defaults to `claude-haiku-5-5`. It refuses without a terminal, inside Claude Code and in CI. The next `report` shows the results.
- The guard asks before the agent runs `harness report` and denies `harness eval`. Both pass with `--help`.

### Presets

- New `harness preset list` and `harness preset check <dir>`: list the shipped and repo presets, or check a preset folder. Both write nothing.
- New shipped preset `khubaib-frontend` (core block, engineering principles, React, Next.js and React Native skills), and `harness select --preset <id> --answers <file>`, which adds ticked rows for the preset's core and the skills that match the stack. A chosen preset is recorded as a `preset` key in the config.
- `/harness:init` asks "Use a named preset?" ("No preset" is the default) and shows the preset's extra lines and its context cost before you confirm. `update` re-renders the preset and follows the stack; "No preset" turns it off.
- New `harness preset install <dir> [--dry-run|--yes]`: checks a preset folder and copies it to `.harness/presets/` (commit it; `uninstall` keeps it).
- New `harness preset install <dir> --global`: installs one preset under `~/.claude` for every repo. It shows each path and its diff, and each write needs its own yes (with `--yes`, only the paths in `--take`). One global preset at a time. `harness uninstall --global` removes exactly what `~/.claude/harness/manifest.json` lists and restores files from their backups.
- New skill `/harness:preset`: builds your own preset through an interview, runs `harness preset check`, then installs it for the repo or globally. New `harness validate preset-answers <file>` checks its answers. It never asks for or stores a git name, email or secret.
- `harness git`: `git branch --suggest <topic>` prints one branch name per preset prefix. With a preset that sets `no_ai_trailer`, `git commit` refuses a set `git.commit_trailer`. With `pr_size_warning`, `git pr` prints a size warning before it creates the PR.

### Lint and TS rules

- New `harness rules [--apply]`: proposes ESLint rules for the stacks it detects (TypeScript, React, Next.js, React Native), all `error`, and the TS options `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch` and `noImplicitReturns`. It first runs your own ESLint and `tsc --noEmit` and prints each one's violation count (unknown when it can't run, never 0). `--apply` asks you to type `yes`, then writes `.harness/eslint/harness.config.mjs`, one import and spread in your `eslint.config.*`, and the TS options in `tsconfig.json`. All of it is in the manifest, so `uninstall` removes it. It never installs a plugin or creates a config.

### Team decisions

- New `harness remember add|confirm|retire|sync|list|check`. `add` writes a decision to `docs/decisions/<id>.md` and a rule, `.claude/rules/harness-decision-<id>.md`, that Claude Code loads when its paths are touched. The write commands ask first and never commit or stage; open a PR. A field that looks like a secret is refused.
- A decision not confirmed for `decisions.expiry_days` (default 90) expires and its rule is dropped at the next sync; `remember confirm <id>` renews it. `remember check` is for CI: it exits 1 on an invalid decision or rules out of sync; stale, expired and oversized decisions are notes.
- New skill `/harness:remember`. The `AGENTS.md` block now says decisions live in `docs/decisions/` and change only through `/harness:remember`.
- Stop: a passing Stop suggests `harness remember add` once per session when you state a standing rule ("from now on…", "we decided…"), and warns once per decision when the session changed code an active decision covers, or when rules are out of sync. Neither blocks. Off with `decisions.nudge: false` (the suggestion) or `checks.decisions: false`.
- `doctor` fails on an invalid decision, rules out of sync or a `harness-decision-*.md` rule harness didn't write, and notes stale, expired and oversized ones. `status` adds a `Decisions:` line.
- Protect: the agent may not write the generated rules, a decision file or a new file in `docs/decisions/`, or remove or restore those folders. Copying into `.claude/rules/` is denied only on a harness name. To change a decision yourself, edit it by hand and run `harness remember sync`; `harness sync` also brings the rules in line.
- Guard: the agent has to ask before `remember add`, `confirm`, `retire` and `sync`, and the ask shows the decision's title, rule, why, paths and the file it writes. The command must be one plain command with literal words. Unattended it is denied.
- New config keys `checks.decisions`, `decisions.max_lines`, `decisions.expiry_days` and `decisions.nudge`.

### PR size

- PR size: new `pr_size.target_lines` (200), `pr_size.max_lines` (400), `pr_size.max_files` (20) and `pr_size.exclude` config keys, and `node .harness/hooks/dispatch.mjs --pr-size [--base <name>] [--head <name>] [--worktree]`, which measures the current branch's PR (with `--worktree`, uncommitted and untracked changes too) and prints JSON, using the branch's approved raise as its max. It exits 0 within the limit, 1 over it and 2 when it can't measure. New `pr-size` check (`checks.prSize`, on by default): before `gh pr create`, or a push to a PR branch harness recorded, goes over `max_lines` or `max_files`, it asks you first, and an unattended run is denied with how to split it. A PR it can't measure runs with a note. While a branch grows, harness also warns once as its committed and uncommitted change passes `target_lines` and once as it passes the max, after edits and at Stop, and suggests splitting it with `pr-ship`; the thresholds announced per branch are kept in `.harness/state/pr-progress.json`. After an attended warning, the agent asks you once, with AskUserQuestion under the header `PR size`; any answer lets the next edit run. If it skipped asking, the next edit on that branch asks once in a permission dialog instead (approve to keep going, or say no and split or raise the limit); unattended runs get the note only. A `PR size` question that carries its own answer is denied, so only your answer counts. AskUserQuestion gets its own PreToolUse and PostToolUse hook groups, which never block a question if the dispatcher fails, so `harness update` changes `.claude/settings.json`. After a warning, `pr-ship` asks you to split now, keep going or raise the limit for this branch: `node .harness/hooks/dispatch.mjs --pr-size-raise --lines <n> [--files <n>]`, which you approve in a dialog (denied unattended), lifts that branch's limit for the warnings and at PR time. It is recorded only on the branch the dialog named. To keep forged hook events out, a command that runs a hook dispatcher by hand without an entry flag, or copies, moves, links, pipes or redirects a hook file, is denied, attended or not. It is a text check that over-matches: `grep x .harness/hooks/dispatch.mjs | head` is denied too.
- New own skill `pr-ship` (default on): it splits a change that is over the PR-size limit into stacked PRs, refactors first, then vertical slices with their tests, each opened with an explicit base.

### Other

- `doctor` notes (never fails) when the default branch is unprotected, or protected without a required check that matches a lint or test job in `.github/workflows`. It asks `gh`, and says "unknown" when `gh` is missing or signed out.
- Stop gate: each Stop step is timed into `.harness/logs/timing.jsonl` (event, step, outcome, ms; no paths or command text). At 5 MB it is renamed to `timing.1.jsonl`.

- `harness eval --kind gates` is not available yet.
- The timing log has Stop steps only; hook calls are added in a later release.
- The PR reviewer (M2) and TDD for other languages.
- The own items under "Not built yet" below.

## Known limits

The full list is in `docs/reference.md#known-limits`. This release adds:

- 32 PR-size limits: text detection only, the unmeasured note, the pause and the agent's question, the raise and the hand-run deny.
- Guard and protect: zsh-only forms and aliases are read as bash; force-push forms, heredoc bodies and message values the text rules can't read; a script the agent wrote that takes a protected path as an argument.
- Context budget: harness measures files, not the live session (`/context` is the truth); the offline estimate probably runs low; plugins enabled outside the catalog picks aren't measured; the on-demand total is the most that could load; the budget asks cover only harness's own commands; using the API sends the measured text to Anthropic; the state card doesn't restore Claude Code's summary of earlier hook messages.
- Team decisions: a decision path built at run time, a script, or `tar -x`/`unzip` with no `-C`/`-d` can still change decision files; change detection fingerprints only the generated rules.

New since 0.2.0-beta.0, unchanged in this release:

- Plugin picks are local only and are missing in cloud sessions.
- `extraKnownMarketplaces` needs folder trust.
- MCP servers need each user's approval.
- `CLAUDECODE` is also set in IDE terminals.
- There is no version-drift check for `git-subdir` plugins without `plugin_version`.
- The agent asks before item changes.
- MCP servers aren't measured before install, and only the person installing is asked about the budget. Plugins and external skills now count the number the catalog records (see Context budget above).
- Under `sandbox: always`, item commands may need the `!` prefix. Unverified, pending the live check.
