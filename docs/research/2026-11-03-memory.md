# Project memory for harness — research note (2026-11-03)

Input for the post-M3 memory spec (research, owner input, spec, plan, build). Not built. Nothing here is decided.
Sources fetched 2026-11-03. Claude Code changelog = https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md

## Summary
- Claude Code already covers personal, machine-local memory well: auto memory (`MEMORY.md` index, topic files,
  timestamps, size limits, injection hardening) plus the CLAUDE.md/AGENTS.md/rules hierarchy. Harness should not
  rebuild any of that; the 2026-10-30 catalog's "remember [discouraged: built-in memory]" still holds.
- The gap is team memory: auto memory "is machine-local" and "not shared across machines or cloud environments", so
  decisions a teammate or a cloud session needs live only in someone's home directory.
- The best-evidenced external design is GitHub Copilot's: repo-scoped facts with code citations, re-checked against
  the current branch before use, expiring unless reinforced. Its vendor A/B: PR merge rate 90% vs 83%.
- Evidence says more always-loaded text is not free: context files raised cost >20% without raising success in one
  study, instruction-following falls as instruction count grows, and stale or poisoned memories propagate errors.
- Recommendation: design B — reviewed decision records in the repo, linked to paths, loaded as a short index,
  checked for staleness against git, written only through a validated, secret-scanned harness command.

  capture or injection hook needs no new event wiring.

## What Claude Code already gives (do not duplicate)
Source unless noted: https://code.claude.com/docs/en/memory
- **CLAUDE.md levels**, concatenated broad to specific: managed policy (`/Library/Application Support/ClaudeCode/
  CLAUDE.md` etc.), user `~/.claude/CLAUDE.md`, project `./CLAUDE.md` or `./.claude/CLAUDE.md`, local
  `./CLAUDE.local.md`. Ancestors load at launch; subdirectory files load on demand when Claude touches a file there.
- **Imports**: `@path`, relative to the importing file, max depth "four hops". Imports "don't reduce its context
  cost". External imports (outside the working directory) need a one-time approval dialog.
- **Rules**: `.claude/rules/*.md`; `paths:` frontmatter scopes a rule to globs, loaded when Read/Write/Edit (or a
  single-file `cat`/`head`) touches a match. `paths` is the only frontmatter field read.
- **AGENTS.md**: read directly (v2.1.277+) only when no CLAUDE.md/CLAUDE.local.md exists; otherwise only via
  `@AGENTS.md` import — the harness's existing approach. Adding a `CLAUDE.local.md` stops direct AGENTS.md reads.
- **Auto memory**: on by default locally; `~/.claude/projects/<project>/memory/`, one dir per git repo shared by
  worktrees [cl 2.1.63]. Types `user`, `feedback`, `project`, `reference`; it "skips anything it can derive from the
  codebase" and anything CLAUDE.md already says. Toggle `autoMemoryEnabled` (user or project settings),
  `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `autoMemoryDirectory` (honoured from project settings only after trust).
- **Load and size limits**: `MEMORY.md` first 200 lines or 25KB at start [cl 2.1.83]; topic files read on demand.
  Over-limit index writes return an explicit error [cl 2.1.210]. CLAUDE.md: target <200 lines; a file >4 MiB is
  skipped; on-demand files truncated at 40,000 chars (200K window) [memory doc, v2.1.309+]. Memory files get an
  ISO `modified` timestamp [cl 2.1.214].
- **`/memory`**: lists CLAUDE.md/local/rules locations, toggles auto memory, opens the folder. `/context` shows what
  loaded. `/doctor prompt-audit` (v2.1.283+) flags stale paths, stale commands and contradictions in instruction
  files — a model-driven, on-demand staleness check that already exists.
- **Compaction**: project-root CLAUDE.md, unscoped rules and auto memory are re-injected from disk; path-scoped
  rules and nested CLAUDE.md reload on demand; hook-added context is only summarised; `SessionStart` with the
  `compact` matcher re-runs. https://code.claude.com/docs/en/context-window
- **Subagents**: get the CLAUDE.md hierarchy (not Explore/Plan, not with `omitClaudeMd`), but not the main auto
  memory (forks excepted). `memory: user|project|local` gives a subagent its own dir; `project` =
  `.claude/agent-memory/<agent>/`, "shareable via version control", the "recommended default"; first 200 lines/25KB
  of its `MEMORY.md` go in its system prompt. https://code.claude.com/docs/en/sub-agents
- **Skills**: description in context every turn (description+`when_to_use` capped at 1,536 chars); body on invoke;
  after compaction 5,000 tokens per skill, 25,000 total. https://code.claude.com/docs/en/skills
- **Hooks**: `SessionStart`/`UserPromptSubmit` `additionalContext` and plain stdout are capped at 10,000 chars (over
  that, a file path and 2,000-char preview). `Stop` gets `last_assistant_message`. `InstructionsLoaded` fires per
  CLAUDE.md/rule load and cannot block. `SessionEnd` budget 1.5 s by default. https://code.claude.com/docs/en/hooks
- **Hardening already in place**: invisible characters and markup-imitating tags are neutralised in `MEMORY.md` and
  recalled notes [cl 2.1.284]; a repo-chosen memory dir is ignored under `blockReadsOutsideWorkingDirectories`
  [cl 2.1.273]; auto memory can't be turned on from background or Claude-spawned sessions [cl 2.1.285].
- **Anthropic's own plugins** (official marketplace): `claude-md-management` (Anthropic) audits CLAUDE.md and has
  `/revise-claude-md` to "capture session learnings"; `remember` is third-party (Digital-Process-Tools, daily logs).
  https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-md-management

Pattern: every vendor keeps must-follow rules in committed instruction files and treats generated memory as a
fallible, personal recall aid. Only Copilot shares generated memory with a team, and it pairs that with citations,
re-verification and expiry.

## Evidence: what helps and what hurts
- **Context rot.** Chroma, 18 models (2025-07-14): reliability drops as input grows, even on simple retrieval; one
  topically similar distractor lowers accuracy, four lower it more. https://www.trychroma.com/research/context-rot
  Anthropic: context is "a finite resource with diminishing marginal returns"; recommends just-in-time retrieval and
  structured note-taking outside the window (2025-09-29).
  https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **Instruction overload.** IFScale (arXiv 2507.11538, 2025-07): accuracy falls with instruction count; best model
  68% at 500 instructions; bias toward earlier instructions. https://arxiv.org/abs/2507.11538
- **Context files.** Gloaguen et al. (arXiv 2602.11988, v1 2026-02): AGENTS.md-style files "do not generally improve
  task success" and raise inference cost >20%; overviews don't help; use them for non-standard practices.
  https://arxiv.org/abs/2602.11988 — Counterpoint, arXiv 2601.20404 (124 PRs, 10 repos): median runtime −28.64%,
  output tokens −16.58%, completion comparable. https://arxiv.org/abs/2601.20404 Mixed; both favour short files.
- **Claude Code guidance.** "every line ... takes a little of Claude's attention on every task"; if emphasis doesn't
  work, the line belongs in a hook; don't describe architecture. https://code.claude.com/docs/en/best-practices
- **Memory helps (vendor numbers).** Anthropic memory tool + context editing: +39% on an internal agentic-search
  eval; context editing alone +29%; −84% tokens on a 100-turn eval (2025-09-29). https://claude.com/blog/context-management
  Copilot (2026-01-15): merge rate 90% vs 83%, review precision +3% / recall +4%, positive feedback 77% vs 75%.
  https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/
  Both vendor-run on their own evals.
- **Stale or wrong memories.** Agents closely follow retrieved past experience and errors in stored experience
  propagate; selective addition and deletion matter (arXiv 2505.16067). https://arxiv.org/abs/2505.16067
  Copilot seeded false memories; agents "consistently verified citations" (qualitative only). Copilot docs: the
  validation is "a judgment", use instructions for must-apply rules.
- **Injection via stored memory.** Rehberger (2024-09-20): prompt injection from untrusted content wrote a ChatGPT
  memory that exfiltrated later chats; fixed in macOS app 1.2024.247.
  https://embracethered.com/blog/posts/2024/chatgpt-macos-app-persistent-data-exfiltration/
  MINJA (arXiv 2503.03704): poisoning agent memory through queries only. https://arxiv.org/abs/2503.03704
  OWASP Agentic Top 10 2026 (2025-12-09) lists ASI06 "Memory & Context Poisoning" (name from secondary sources).
  https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/
- **Privacy and secrets.** Codex redacts secrets in generated memory and says not to store them [8]. Copilot user
  preferences can include direct quotes, visible to org admins on Business/Enterprise [6]. claude-mem offers
  `<private>` exclusion [14]. No Claude Code doc found on secret handling in auto memory.
- **Team vs personal.** Claude Code splits CLAUDE.md (team, git) from CLAUDE.local.md and auto memory (personal).
  Copilot splits repo facts from user prefs and never applies user prefs in code review [6].
- **Review and expiry.** Copilot: 90-day expiry, reset by reinforcement [6]. ADRs keep reversed decisions marked
  "superseded", not deleted (Nygard, 2011). https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions

## Risks for a harness memory feature
1. Context bloat: every always-loaded line costs attention and tokens; an index that grows unchecked recreates the
   problem auto memory caps at 200 lines.
2. Duplication or conflict with auto memory, CLAUDE.md and `product.md`; contradicting files make Claude "pick one
   arbitrarily" (memory doc).
3. Stale entries that outlive the code they describe, followed confidently (2505.16067).
4. Poisoning: a memory drafted from a web page, PR text or tool output becomes a standing instruction for every
   teammate's session. Repo files don't get the 2.1.284 neutralisation that auto memory gets.
5. Secrets or personal data committed to git, then pushed.
6. Unattended runs writing memory nobody reviews.
7. Overlap with existing tools (`/doctor prompt-audit`, `claude-md-management`), making harness the third way to do it.

## Candidate designs

### A. Hygiene only (no new store)
Harness adds checks around what Claude Code already has: `doctor` reports line counts of CLAUDE.md, AGENTS.md and
rules against the 200-line guidance, and paths named in them that no longer exist in git; the AGENTS.md block tells
the agent that team facts go into AGENTS.md or `.claude/rules/` through a PR, personal ones into auto memory.
- For: least code; no new file type; deterministic and CI-able, unlike `prompt-audit`.
- Against: no capture, no link from a decision to code, no expiry; does not close the team gap.

### B. Reviewed decision records in the repo (recommended)
- One file per decision, e.g. `docs/decisions/NNNN-slug.md`, frontmatter `status` (active/superseded), `paths`
  (globs), `verified_at` (commit sha), body ≤ ~10 lines, ADR-style.
- Loading: a generated one-line-per-entry index (hard cap, e.g. 20 lines) inside the AGENTS.md block or an
  `@`-imported file; bodies read on demand. Optionally a generated `.claude/rules/` file per entry with `paths`, so
  it loads only near its code.
- Writing: only through `harness remember` (CLI + `/harness:remember` skill). It validates the schema, runs the
  secret scan (gitleaks is already a catalog item), refuses text quoted from tool output or web content without the
  user's confirmation, and asks before writing. Review is the normal PR; harness never commits on its own.
- Staleness: `doctor` and the Stop gate flag entries whose `paths` no longer match any tracked file, and entries
  whose linked files changed since `verified_at`. "Re-verify" bumps the sha; "retire" sets `superseded`.
- For: team-shared, works in cloud sessions (repo files load there), linked to code, review via PR, deterministic
  staleness; mirrors Copilot's citation idea without a model call.
- Against: most build effort; needs humans to merge; the index still costs context on every session.

### C. B plus hook-driven capture
B, plus a `Stop`/`SessionEnd` check that spots capture signals in `last_assistant_message` or the turn (the user
corrected the agent, a gate was overridden, a decision was stated) and writes a candidate to a gitignored inbox
(`.harness/memory/inbox/`). `SessionStart` shows "N candidates waiting: run /harness:remember".
- For: captures what people forget to write down; no model call if heuristic.
- Against: heuristic signals are noisy (unmeasured); a model-based extractor costs money; an inbox nobody empties.
  Defer until B shows use.

### D. Subagent project memory for the reviewer
Set `memory: project` on `staff-reviewer` so review learnings land in `.claude/agent-memory/staff-reviewer/`, a
built-in feature with near-zero code. Harness adds a guard `ask` on writes there and a PR-diff mention.
- For: uses Claude Code's own mechanism; the reviewer gets better per repo.
- Against: the reviewer (M2) isn't built; agent writes into committed files that teammates load; off whenever auto
  memory is off.

**Recommendation:** B, with A's size and dead-path checks folded into `doctor`. Keep C and D as later options with
explicit triggers (C when users ask for capture; D when M2 ships). Keep `remember` discouraged in the catalog.

## Open questions for the owner (spec interview)
1. **Scope.** (a) Team-shared decisions only [recommended: personal stays in built-in auto memory]; (b) team + a
   personal tier harness manages; (c) personal only.
2. **Where entries live.** (a) `docs/decisions/` [recommended: visible to humans and every other agent tool, ADR
   convention]; (b) `.harness/memory/`; (c) `.claude/rules/` directly.
3. **How they load.** (a) Capped index in the AGENTS.md block, bodies on demand [recommended]; (b) path-scoped rules
   generated per entry; (c) on demand only through a skill; (d) `SessionStart` injection (10,000-char cap, only
   summarised after compaction unless matched on `compact`).
4. **Index cap.** (a) 20 lines [recommended: block is already ≤60]; (b) 40; (c) configurable with a default.
5. **Who writes.** (a) Agent drafts through `harness remember`, user approves the write, PR reviews it
   [recommended]; (b) humans only; (c) agent writes freely, PR is the only check.
6. **Capture trigger.** (a) Manual only in v1 [recommended]; (b) Stop-hook nudge on signals (design C); (c) automatic
   model extraction (paid; needs per-run OK).
7. **Staleness policy.** (a) Git checks: dead `paths` and changed-since-`verified_at` [recommended]; (b) time
   expiry like Copilot's 90 days; (c) both; (d) none.
8. **Where staleness is enforced.** (a) `doctor` and a Stop-gate warning, never a block [recommended]; (b) Stop-gate
   block; (c) a CI item.
9. **Unattended runs.** (a) No memory writes; candidates logged only [recommended]; (b) same as interactive; (c) off.
10. **Untrusted input.** (a) Refuse drafts that quote tool output, PR text or web content unless the user confirms
    [recommended]; (b) warn only; (c) rely on PR review.
11. **Built-in auto memory.** (a) Leave it alone [recommended]; (b) offer a "promote to team decision" command that
    reads `~/.claude/projects/.../memory` (reads the user's home dir; privacy); (c) turn it off per repo.
12. **Reviewer memory (design D).** (a) Defer until M2 [recommended]; (b) ship with this feature; (c) never.
13. **`product.md`.** (a) Stays separate as product scope [recommended]; (b) becomes the first decision record.
