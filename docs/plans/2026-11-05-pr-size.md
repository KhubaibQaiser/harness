# PR size implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** harness warns while a branch's change grows, once past 200 changed lines and once past 400 lines or 20 files, and the agent then asks the person to split, keep going or raise the limit (spec §14). As the last check, a `pr-size` check measures every `gh pr create`, and every `git push` to a branch harness recorded as a PR, without a shell. It asks above the limit, denies when unattended, and notes when it can't measure. A `pr-ship` skill, installed by `init`, plans the split into stacked PRs of about 200 lines.

**Architecture:**
- `walkCommands` is extracted from the guard's `personOnlyInvocation`/`walkInvocation` (`src/checks/guard.ts:197-301`). The person-only rules become one visitor. pr-size adds a second visitor that finds PR creates and pushes.
- `src/checks/pr-size/` holds four focused files, like `src/checks/tdd/` and `src/checks/stop/`:
  - `measure.ts`: base and head resolution, the three-dot diff and the counting rules;
  - `detect.ts`: the visitor, giving `PrTarget[]`;
  - `entry.ts`: the `--pr-size` entry of `dispatch.mjs`;
  - `check.ts`: the decision, the copy and the `pr-branches.json` record;
  - `progress.ts` (Task 10): the in-progress warnings and `pr-progress.json`.
- The warnings run at PostToolUse on the edit tools and once at Stop. They are delivered as `additionalContext` for the agent and `systemMessage` for the person (spec §14.2 and §14.3; Task 8 adds the `notice` field). A raise needs the person's yes in a permission dialog (§14.4).
- Every git call goes through an injected `Git` function. Tests use temporary repos (`makeRepo`) or a fake `Git`. Nothing touches the network.
- The `pr-ship` own item ships the skill template and, from Task 7, owns `checks.prSize`. `pr-create-trigger` is marked as replaced.

**Tech stack:** TypeScript, Node ≥ 22.11, esbuild bundle, Vitest, picomatch (already a dependency, through `matches`). **No new dependency.**

**Spec:** `docs/specs/2026-11-03-pr-size-design.md` (owner-approved, binding). Section numbers below (§n) refer to it. The evidence is in `docs/research/2026-11-02-pr-size.md`.

## Global constraints

- Limits (D2): target 200, ask above 400 changed lines or above 20 files. "Over" means `lines > max_lines || files > max_files` (§6).
- Counting (§5, D3, O1-O3):
  - Tests count.
  - Lockfiles, `.*ignore` files except `.npmignore` and `.harnessignore`, snapshots and `multi_file_gate.generated` paths don't count.
  - A binary file is 1 file and 0 lines. A whole-file deletion is 1 file and 0 lines. A rename is judged by its new path.
  - At PR time, only committed work counts, from the three-dot diff. The in-progress warnings also count staged, unstaged and untracked changes (spec §14.6).
- Unmeasured (O5) allows with the §10.3 note and one `pr-size-unmeasured` event, attended and unattended. It never asks or denies.
- Trust boundary (§4): a base or head name must match `^[A-Za-z0-9][A-Za-z0-9._/-]{0,254}$` and contain no `..`. Only resolved SHAs reach `git diff`. Every lookup uses `rev-parse --verify --quiet --end-of-options <ref>^{commit}`.
- No shell: `spawnSync('git', args, { cwd, encoding: 'utf8', timeout ≤ 2000, maxBuffer: 64 MB })`, and 6 s in total per measurement.
- A command with no PR create and no push spawns no git and reads no record file (PE latency budget).
- The warnings: a Bash PostToolUse spawns no git, and neither does an edit outside the repo or to an excluded path. An unmeasured in-progress measurement is silent (spec §14.6).
- Only the PostToolUse after an allowed run of the detected `--pr-size-raise` command writes a raise (§14.4).
- No new regex rules in the guard's `DENY` or `ASK` (PE §3.5). The guard's tests pass unchanged.
- No changes to `src/vet/*`, `src/cli/vet.ts` or `guard.ts:302-346`.
- Copy: §10 and §14 verbatim, with the push wording from N7. Paths and branch names in any message go through `esc` (`src/core/config.ts:92`).
- Lean context: the `pr-ship` description is one line of at most 160 characters. The skill is under 60 lines.
- Tests:
  - TDD: red first.
  - Every git call goes to a temporary repo or a fake `Git`.
  - No network, no `gh` call, no `claude -p` and nothing paid. The three §11 live checks are out of this plan; they need the owner's approval as one batch.
  - The full suite must pass with `claude` off PATH: ``PATH="$(node -p "process.env.PATH.split(require('path').delimiter).filter(d=>!require('fs').existsSync(require('path').join(d,'claude'))).join(require('path').delimiter)")" pnpm test``.

## Review focus

1. **A huge PR overflows the spawn buffer.** With the default 1 MB `maxBuffer`, a numstat over 1 MB fails as `ENOBUFS`. The PR would then be unmeasured and allowed, exactly the case the check exists for. `realGit` sets 64 MB (Task 3 test: a 2 MB blob read through `realGit` arrives whole).
2. **A corrupt `pr-branches.json` or `pr-progress.json`.** Invalid JSON, an array, or an entry with string counts must read as "no record". A throw there would deny every later push, because the check is `failClosed`, or turn every edit's PostToolUse into feedback. PostToolUse never throws (Task 7 and Task 10 tests).
3. **The pause ask goes wrong.** Three failures are possible:
   - it asks on every edit forever;
   - it never asks;
   - it asks on a branch that wasn't warned.

   Expected: one ask after each attended warning. It is cleared by the edit running, by the person's next prompt, or by a raise, and only for the checked-out branch. With no `pending` entry there is no git spawn (Task 12 tests).
   A branch named `constructor` or `toString` is still read only through `Object.hasOwn` (Tasks 7, 10 and 12 tests).
4. **A flood of untracked files.** In a repo where `node_modules` isn't gitignored, every edit would list tens of thousands of untracked files and read them, and the edit hook would slow to seconds. At most 2,000 are read; past that they count as files only, and the warning says the change is over the max. Task 9 test: 3,000 files in under 2 s. (Control and bidi characters in names stay covered by the `esc` tests in Tasks 7 and 10.)
5. **The agent raising its own limit.** Only a raise the person approved may be recorded. A hidden form (`$X --pr-size-raise …`) gets past the PreToolUse ask, so PostToolUse must not record it either. Detection is the same function on the same text at both events (Task 11 test). The skill's own measuring command still passes the guard and protect without an ask (Task 4 test). Known limit: a base whose last segment is a guard backstop word (`feat/sync`) asks.

### Task 3: Measuring a PR

**Files:**
- Create: `src/checks/pr-size/measure.ts`
- Test: `test/checks/pr-size/measure.test.ts`

**Interfaces:**
- Consumes: `HarnessConfig` (Task 2), `matches`, `esc`.
- Produces:
  - `export type Git = (args: string[], timeoutMs: number) => { status: number | null; stdout: string; error?: NodeJS.ErrnoException }`.
  - `export const realGit = (root: string): Git`. It runs `spawnSync('git', args, { cwd: root, encoding: 'utf8', timeout, maxBuffer: 64 * 1024 * 1024, stdio: ['ignore', 'pipe', 'pipe'] })`.
  - `export const plainBranch = (n: string): boolean`, the §4 rule.
  - `export type SizeConfig = Pick<HarnessConfig, 'pr_size' | 'multi_file_gate' | 'stop'>`.
  - `export interface Size { base: string; head: string; lines: number; files: number; top: { path: string; lines: number }[]; excluded: string[] }`.
    - `base` is shown as `origin/<n>` when it was found in `refs/remotes/origin/`, and as written otherwise.
    - `head` is `HEAD` or the name.
    - `top` holds every counted file, sorted by lines descending, then by path.
    - `excluded` is sorted.
  - `export interface Unmeasured { error: string; base?: string }`.
  - `export function measure(root: string, want: { base?: string; head?: string }, config: SizeConfig, opts?: { git?: Git; now?: () => number; budgetMs?: number }): Size | Unmeasured`. The default `budgetMs` is 6000.
  - `export const isOver = (s: Pick<Size, 'lines' | 'files'>, c: HarnessConfig['pr_size']): boolean`.
  - `export function currentBranch(git: Git): string | null`. It runs `symbolic-ref --quiet --short HEAD` and returns null when HEAD is detached.
- Unmeasured reasons, exactly:
  - `` base `<n>` not found; fetch it first ``
  - `` head `<n>` not found ``
  - `` `--base` is not a plain branch name `` (or `` `--head` ``)
  - `no base: origin/HEAD is not set and stop.base_ref (<ref>) was not found; fetch it first`
  - `git not found` (for `ENOENT`)
  - `git timed out` (for `ETIMEDOUT`, or no budget left)
  - `git diff failed`

  Every `<n>` goes through `esc`.
- Base lookup:
  - The `--base` value; otherwise `symbolic-ref --quiet --short refs/remotes/origin/HEAD`; otherwise `stop.base_ref`.
  - Each name is tried as `refs/remotes/origin/<n>`, then `refs/heads/<n>`, then `<n>` (drift 9), each with `rev-parse --verify --quiet --end-of-options <ref>^{commit}`.
- Head lookup: `refs/heads/<n>`, then `refs/remotes/origin/<n>`; with no name, `HEAD`.
- Each call's timeout is `min(2000, deadline - now())`. When that is ≤ 0, the result is `git timed out` and no call is made.
- The two diff calls are exactly the §4 commands, with `-c core.quotePath=false` first in `args`.
- Parsing `-z` numstat (the one algorithm the signature doesn't fix): split on `\0`. Each record is `added\tdeleted\tpath`. When `path` is empty, the next two fields are `old` and `new`, and `new` is judged. `-` counts are binary: 0 lines. The `--diff-filter=D` paths (`D\0path\0` pairs) count 0 lines.
- A path is excluded when `matches(rel, [...pr_size.exclude, ...multi_file_gate.generated])`.

    - `pnpm-lock.yaml`, `.gitignore`, `.prettierignore`, `.dockerignore`, `.eslintignore` and `pkg/.gitignore` are in `excluded` and counted in neither;
    - `.npmignore` and `.harnessignore` are counted;
    - `__snapshots__/a.snap` and `x.snap` are excluded;

    - a binary file (bytes with NUL) is 1 file and 0 lines;
